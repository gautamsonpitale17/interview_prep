1.  What is the difference between var, let, and const?

    When declaring a variable in JavaScript, first choose between const, let, and var based on how the variable needs to behave. If the variable should not be reassigned, use const, which is block-scoped and cannot have its binding reassigned after initialization. If the variable needs to be reassigned, use let, which is also block-scoped but allows reassignment. Both let and const are hoisted but remain in the Temporal Dead Zone (TDZ) until their declaration is reached. If old function-scoped behavior, redeclaration, or legacy compatibility is specifically required, var can be used; it is function-scoped, hoisted, initialized to undefined, and can be redeclared. Therefore, modern JavaScript generally follows the process of const by default → let when reassignment is needed → var only for legacy or specific cases.

2.  Explain closures in JavaScript with an example.

    When JavaScript executes an outer function, it creates a new lexical scope containing its local variables. If an inner function is defined inside that outer function and accesses one of those variables, JavaScript creates a link between the inner function and the surrounding scope. When the outer function finishes, its execution ends, but if the inner function is still referenced outside the outer function, that link keeps the required variables alive in memory, forming a closure. The inner function can then continue to access and modify those variables through the preserved scope. If the inner function is not referenced anywhere after the outer function finishes, the scope and its variables can eventually become eligible for garbage collection.

3.  What is hoisting in JavaScript?

    When JavaScript starts executing a script or enters a function, the engine first goes through a creation phase, where it scans the current scope and registers all declarations before executing any code. For a var declaration, the variable is hoisted and initialized with undefined, so accessing it before its declaration returns undefined. For let and const, the variables are also hoisted and registered, but they remain in the Temporal Dead Zone (TDZ) until execution reaches their declaration, so accessing them early causes a ReferenceError. Function declarations are handled differently: the function's name and entire body are hoisted, allowing the function to be called even before its declaration appears in the code. After this creation phase is complete, JavaScript enters the execution phase and runs the code line by line, initializing variables when their declaration statements are reached.

4.  Explain the concept of the "this" keyword in different contexts.

    When a JavaScript function is called, the value of this is determined by how the function is invoked, not where it was defined. First, if it is an arrow function, it does not create its own this and instead uses the this value from its surrounding lexical scope. For a regular function, JavaScript then checks whether it was called with new; if so, this refers to the newly created object. Otherwise, it checks for explicit binding through call, apply, or bind, which directly specifies the this value. If neither applies, JavaScript checks for implicit binding, where a call such as object.method() makes this refer to the object before the dot. Finally, if the function is called normally without any special binding, default binding applies: this is undefined in strict mode and the global object in non-strict mode.

5.  What is the difference between == and === ?

    When JavaScript compares two values using == or ===, it first checks whether their types are the same. If the types match, both operators compare the values directly and generally produce the same result. If the types are different, === immediately returns false because strict equality never performs type conversion, while == continues by applying JavaScript's type coercion rules to convert the values into compatible types before comparing them. For example, with 1 == "1", JavaScript converts the string "1" into the number 1, so the comparison returns true, whereas 1 === "1" returns false. Therefore, the practical process is same types → compare directly; different types + === → false; different types + == → perform coercion → compare.

6.  What are JavaScript data types (primitive vs reference)?

    When JavaScript works with a value, it first falls into one of two categories: primitive or object. If the value is a primitive, it belongs to one of seven types: string, number, boolean, undefined, null, symbol, or bigint; primitives are immutable and are copied and compared by their values, so assigning one variable to another creates an independent value. If the value is an object, it is a reference type, which includes objects, arrays, functions, dates, maps, sets, and other built-in objects; these values can be mutated, and variables hold references to the same underlying object rather than independent copies. As a result, copying an object variable copies its reference, so changes made through one variable can be visible through the other, while two separately created objects with identical contents are still considered different references.

7.  Explain event bubbling and event capturing.

    When a DOM event occurs, the browser begins the event flow from the top of the document and moves toward the element where the event happened. First, the event travels downward during the capturing phase, moving from window through the document and its ancestor elements toward the target. It then reaches the target phase, where the event arrives at the element that triggered it. After that, the event travels upward through the ancestors during the bubbling phase, eventually reaching window. Event listeners run according to the phase in which they are registered: normal addEventListener listeners use bubbling by default, while { capture: true } registers a capturing listener. At any point during this flow, event.stopPropagation() can stop the event from continuing to other elements in the propagation path, while event.preventDefault() only prevents the browser's default action and does not stop propagation.

8.  What is the event loop in JavaScript?           

    When JavaScript starts running, synchronous code is executed on the call stack one operation at a time. When the code encounters an asynchronous operation such as setTimeout, fetch, or a DOM event, that operation is handled by the browser or runtime environment instead of blocking the call stack, allowing the remaining synchronous code to continue. Once the asynchronous operation is ready, its callback is placed into the appropriate queue: microtasks for Promise callbacks and queueMicrotask, or macrotasks for timers, I/O, and events. The event loop continuously checks whether the call stack is empty, and when it is, it first drains the entire microtask queue before taking a single macrotask and placing it on the call stack. That task then executes normally, and the event loop repeats the same process continuously, which allows JavaScript to remain single-threaded while efficiently coordinating asynchronous operations.

9.  Difference between synchronous and asynchronous code.

    When JavaScript encounters an operation, it first determines whether the operation is synchronous or asynchronous. If it is synchronous, the operation runs directly on the call stack, and JavaScript waits for it to finish before moving to the next line, meaning a long-running operation can block the thread and, in a browser, make the UI unresponsive. If it is asynchronous, the operation is handed off to the surrounding environment, such as the browser or Node.js runtime, so the JavaScript call stack can immediately continue executing other code instead of waiting. When the asynchronous operation finishes, its result is delivered back to JavaScript through a callback, Promise, or await, which is then scheduled for execution through the event loop. This allows JavaScript to remain single-threaded while avoiding unnecessary blocking during operations such as timers, network requests, and I/O.

10. What are Promises? Explain then(), catch(), and finally().

    When JavaScript creates a Promise using new Promise(executor), the executor function runs immediately and synchronously, while the Promise itself starts in the pending state. The executor performs or starts the required operation and eventually calls either resolve(value) or reject(error). If resolve() is called, the Promise transitions permanently from pending to fulfilled and the value becomes available to .then() handlers; if reject() is called, it transitions permanently to rejected and the error or reason is handled by .catch(). Once settled, a Promise cannot switch to another state. After the success or failure handlers complete, .finally() can run regardless of the outcome, making it useful for cleanup operations. These handlers are scheduled asynchronously when the Promise settles, allowing Promise-based code to work naturally with JavaScript's event loop and forming the foundation for async/await.

11. Explain async/await and how it relates to Promises.

    When an async function is called, it begins executing synchronously until it reaches an await expression. At that point, JavaScript pauses only the execution of that async function and returns control to the surrounding program, allowing the event loop and other code to continue running without blocking. The Promise passed to await then settles in the background. If it fulfills, the async function resumes from where it paused and receives the resolved value; if it rejects, the await expression throws the rejection as a JavaScript error, which can be handled using try/catch. The function continues until it finishes or an uncaught error occurs, and regardless of how it completes, an async function always returns a Promise: fulfilled with its return value on success or rejected with the error on failure.

12. What is the difference between call(), apply(), and bind()?

    When you need to manually control the value of this inside a function, JavaScript provides call(), apply(), and bind(). First, decide whether the function should execute immediately or later. If it should execute later, use bind(), which creates and returns a new function with the specified this value and optionally pre-filled arguments, without executing the original function. If the function should execute immediately, choose between call() and apply() based on how the arguments are available: use call() when passing arguments individually, or apply() when passing them together as an array or array-like object. Therefore, the process is execute later → bind(); execute now + individual arguments → call(); execute now + arguments array → apply().

13. Explain prototypal inheritance in JavaScript.

    When JavaScript evaluates a property access such as obj.property, it first checks whether the property exists directly on the object itself. If it exists, JavaScript immediately returns that value. If it does not, JavaScript follows the object's hidden [[Prototype]] link and checks the next object in the prototype chain. This process continues from one prototype to the next, checking each object for the requested property until it is found. If the property is found on a prototype, its inherited value is returned; if the chain eventually reaches null without finding the property, JavaScript returns undefined. This prototype chain is the foundation of JavaScript's inheritance system and is also what allows objects created through constructors or class syntax to share methods through their prototypes rather than storing separate copies on every instance.

14. What is the difference between null and undefined?

    When JavaScript encounters an absence of a value, it can represent it using either undefined or null, depending on how that absence occurs. If the value has not been assigned or is missing automatically, JavaScript typically produces undefined, such as for an uninitialized variable, missing function argument, missing return value, or nonexistent object property. If the developer intentionally wants to represent an empty or absent value, they can explicitly assign null. Although both represent the absence of a value, JavaScript treats them as different types: typeof undefined returns "undefined", while typeof null returns "object" because of a historical language quirk. When comparing them, null == undefined returns true due to a special loose-equality rule, whereas null === undefined returns false because strict equality does not perform type coercion.

15. What are higher-order functions? Give an example.

    When a JavaScript function is evaluated to determine whether it is a higher-order function, check whether it accepts a function as an argument or returns a function as its result. If neither occurs, it is a regular function that works with ordinary values. If it accepts another function, such as the callback passed to map(), filter(), or addEventListener(), it qualifies as a higher-order function. If it returns another function, such as a debounce() utility or a curried function, it also qualifies. A function can do both at the same time, meaning it can receive functions as arguments and return a new function. This behavior is possible because JavaScript treats functions as first-class values, allowing them to be stored, passed, and returned like other data.

16. Explain the concept of debouncing and throttling.

    When a function is triggered repeatedly by a high-frequency event such as typing, scrolling, or resizing, first decide whether the function should wait until the activity stops or run periodically during the activity. If it should wait for a pause, use debouncing: each new call resets the timer, and the function executes only after no new call occurs for the specified delay, typically using the arguments from the latest call. If the function should continue running at a controlled rate during ongoing activity, use throttling: the first call is allowed to execute, a cooldown period begins, and additional calls during that period are ignored until the next execution window becomes available. Both techniques wrap the original function and return a new function that controls when the original function is allowed to run.

17. What is a callback function? What is callback hell?

    When an asynchronous operation needs to perform some action after it finishes, a callback function can be passed to that operation and executed when the result is ready. If the callback needs to start another asynchronous operation, another callback is placed inside it, creating another level of nesting. When each subsequent operation depends on the previous result, this nesting continues to grow, producing callback hell, where the code becomes increasingly difficult to read, debug, maintain, and handle errors in. To avoid this deep nesting, the same sequence can be rewritten using Promises or async/await, which flatten the asynchronous flow into a more readable, linear structure.

18. Explain the difference between shallow copy and deep copy.

    When copying an object or array in JavaScript, first determine whether the data contains nested objects or arrays that need to be independent. If a shallow copy is used, JavaScript creates a new top-level object or array but copies nested objects and arrays by reference, meaning both structures still share the same nested data and mutations to that nested data can affect both. If a deep copy is used, JavaScript recursively creates new copies of the nested objects and arrays as well, resulting in two completely independent structures with no shared references. Therefore, use a shallow copy such as spread syntax or Object.assign() when shared nested references are acceptable or the data is flat, and use a deep-copy mechanism such as structuredClone() when nested data must be fully independent.

19. What are arrow functions and how do they differ from regular functions?

    When defining a function in JavaScript, first determine whether the function needs its own this binding, its own arguments object, or constructor behavior with new. If any of these are required, use a regular function because arrow functions do not provide these features. Otherwise, an arrow function can be used, providing a concise syntax and a lexical this that is inherited from the surrounding scope. After choosing an arrow function, determine whether the function consists of a single expression: if so, braces and return can be omitted and the expression is implicitly returned; if the function requires multiple statements, use braces with an explicit return when a value needs to be returned.

20. Explain the concept of currying in JavaScript.

    When a curried function is called, it receives an argument and stores that value using a closure rather than immediately executing the original function. It then checks whether enough arguments have been collected to satisfy the original function's requirements. If not, it returns another function that is ready to receive the next argument, and this process repeats, with each returned function preserving the previously collected arguments through its closure. Once all required arguments have been gathered, the original function is executed using the complete set of collected arguments, and its final result is returned.

21. What is the difference between map(), filter(), and reduce()?

    When processing an array in JavaScript, first determine what kind of result you need. If every element needs to be transformed while keeping the same number of elements, use map(), which creates a new array containing one transformed value for each input element. If the goal is to select only the elements that satisfy a condition, use filter(), which creates a new array containing the elements that pass the test. If the goal is to combine or accumulate the elements into a single result, use reduce(), which processes each element while maintaining an accumulator and ultimately returns one value, such as a number, string, object, or even another array. Therefore, the basic decision is transform each item → map(); keep matching items → filter(); combine items into one result → reduce().

22. What are JavaScript modules (import/export)?

    When JavaScript code needs to be divided across multiple files, you can use a module system so each file has its own scope and explicitly controls what it shares. If using ES Modules (ESM), a file exposes values with export and another file accesses them with import; these imports are statically analyzed, allowing tools such as bundlers to perform optimizations like tree-shaking. If using CommonJS (CJS), a file exposes values through module.exports and another file loads them with require(), which is evaluated dynamically and synchronously at runtime. Regardless of the module system, once a module is loaded, its execution is cached, so subsequent imports or requires of that module reuse the existing module instance rather than executing its code again.

23. Explain the concept of the temporal dead zone (TDZ).

    When JavaScript enters a scope containing a let or const declaration, the variable is registered during the setup phase but remains uninitialized, which marks the beginning of its Temporal Dead Zone (TDZ). If execution attempts to access the variable before reaching its declaration line, JavaScript immediately throws a ReferenceError. Execution continues normally if the variable is not accessed during this period, and once the declaration executes and initializes the variable, the TDZ ends and the variable becomes available for normal use. Therefore, the process is enter scope → register let/const as uninitialized → access before declaration? → ReferenceError; otherwise → declaration executes → TDZ ends → variable becomes usable.

24. What is memoization, and how would you implement it?

    When a memoized function is called with a set of arguments, it first generates or identifies a cache key for those inputs and checks whether a result for that key already exists. If the result is found, the function immediately returns the cached value, avoiding the expensive computation. If no cached result exists, the function executes its original computation, stores the resulting value in the cache using the input arguments as the key, and then returns that result. On future calls with the same inputs, the cached result can be returned directly instead of repeating the computation. This works reliably when the function's output consistently depends on its inputs, so memoization is primarily appropriate for pure or effectively deterministic functions, while the cache also consumes additional memory.

25. Explain the differences between local storage, session storage, and cookies.  

    When JavaScript needs to store data in the browser, first determine whether the server needs to receive the data automatically. If yes, use cookies, because cookies are automatically included with relevant HTTP requests and can also be configured with security attributes such as HttpOnly. If the data only needs to remain on the client, determine whether it should survive after the current tab is closed. If it should persist, use localStorage, which remains available until explicitly cleared; if it should exist only for the current tab session, use sessionStorage, which is cleared when that tab's session ends. Therefore, the basic decision is server communication → cookies; client-side persistence → localStorage; client-side, tab-scoped temporary storage → sessionStorage.
